# Публикация на Vercel

Проект использует Express и Node.js 24. Сборка фронтенда не требуется:
Vercel обслуживает файлы из `public/`, а `server.js` экспортирует Express-приложение.

## 1. Подготовить базу аккаунтов

Создайте базу в [Turso](https://turso.tech/) и получите её URL вида
`libsql://имя-базы.turso.io` и токен с правом записи.
На Vercel локальный SQLite-файл не подходит: изменения не сохраняются между запусками.

Аккаунты и сессии будут храниться в Turso. Заявки и телефоны по-прежнему хранятся
в localStorage браузера. Серверные таблицы создаются автоматически при первом запуске.

## 2. Настроить проект Vercel

1. Загрузите проект в свой Git-репозиторий и импортируйте его через **Add New → Project** в Vercel.
2. Укажите **Root Directory** — папку с `package.json`, `server.js`, `vercel.json`.
   Если загрузили весь текущий workspace, это `iphone-`; если сам репозиторий проекта — `./`.
3. **Framework Preset:** Express (также указан в `vercel.json`). **Node.js:** 24.x.
4. Оставьте **Build Command** и **Output Directory** без ручного переопределения.
   Команда установки — `npm ci`.
5. Добавьте переменные окружения для **Production**, при необходимости также для **Preview**:

| Переменная | Значение |
| --- | --- |
| `TURSO_DATABASE_URL` | URL базы из Turso |
| `TURSO_AUTH_TOKEN` | Токен базы с правом записи |
| `ADMIN_PASSWORD` | Собственный пароль первого администратора, минимум 12 символов |
| `ADMIN_LOGIN` | Необязательно: логин, по умолчанию `admin` |
| `ADMIN_NAME` | Необязательно: имя, по умолчанию `Админ` |

6. Нажмите **Deploy**. После изменения переменных сделайте **Redeploy**.
7. Откройте опубликованный адрес и войдите с логином администратора и заданным паролем.

В Turso создаётся новый администратор. Локальные аккаунты из `data.db` автоматически
не переносятся: создайте нужных продавцов в «База → Продавцы».
Переменные `ADMIN_*` применяются только при отсутствии администратора в базе.
Для смены существующего пароля используйте «База → Продавцы».
Для Preview используйте отдельную базу, если не хотите менять рабочие аккаунты при проверках.

Альтернатива через CLI из корня проекта:

```sh
npx vercel
# Настройте те же переменные в проекте Vercel перед production-развёртыванием.
npx vercel --prod
```

Не загружайте `data.db`, `.env`, токены или логи в репозиторий.
Они исключены через `.gitignore` и `.vercelignore`.

## 3. Перенести заявки и телефоны с localhost

localStorage привязан к адресу сайта. Публикация не копирует данные из браузера автоматически.

1. На `http://localhost:3000` войдите, во вкладке **База** раскройте **Резервная копия базы**
   и нажмите **Экспорт базы**. Сохраните JSON-файл.
2. На постоянном адресе Vercel войдите администратором и в том же блоке нажмите **Импорт базы**.
3. Выберите файл и подтвердите замену локальных заявок и телефонов.

В файл входят заявки, телефоны и складские остатки; аккаунты и пароли не экспортируются.
На каждом устройстве своя база. Аккаунты в одном браузере и на одном адресе используют
общие заявки и телефоны. Очистка данных сайта удалит локальную базу, поэтому делайте экспорт.
При смене домена повторите перенос. На свежем домене без импорта локальная база будет пустой.

## Локальная разработка

```sh
npm ci
npm start
# http://localhost:3000
```

Нужен Node.js 24. Без настроенного Turso используется существующий локальный `data.db`.
Для новой локальной базы вход — `admin / admin`, если не задан `ADMIN_PASSWORD`.
Чтобы проверить удалённую базу локально, скопируйте `.env.example` в `.env` и заполните значения.
`npm start` и `npm run dev` автоматически читают этот файл.
`DB_FILE` задаёт путь локальной базы; `PORT` — порт сервера.

Проверки:

```sh
npm run check
npm test
```

Проверка интерфейса в Chrome/Chromium:

```sh
npm run test:mobile
```

Она использует временный профиль и тестовую базу, проверяет ширины 320, 360, 390, 430, 768
и 1280 px, основные вкладки, создание и редактирование заявки, короткий экран и склад продавца.
Снимки экранов и отчёт сохраняются в `.artifacts/mobile/`. Браузер при необходимости
можно указать переменной `CHROME_PATH`. Проверка в Chromium не заменяет проверку клавиатуры
и безопасных отступов на физическом iPhone/Safari.

Для Telegram Mini App используйте постоянный HTTPS-адрес Vercel в настройках кнопки меню бота.

Основание конфигурации: [Express на Vercel](https://vercel.com/docs/frameworks/backend/express),
[SQLite на Vercel](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel),
[клиент Turso](https://tursodatabase.github.io/libsql-client-ts/).
